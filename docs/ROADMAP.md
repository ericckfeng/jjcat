# 改進構想（ROADMAP）

討論用的清單，不是承諾。做之前先跟使用者確認範圍；動到資料格式要先讀 `DATA_FORMAT.md` 的相容性規則。

## 原則（所有構想都要符合）
- 長輩好用：大字、大按鈕、一頁只做一件事，不把功能塞回首頁。原本「常吃清單按一下就記」的簡單流程一定保留，新功能是另一條路。
- **同一件事只有一種操作方式**（2026-11-19 決定）：例如記一樣和記多樣都是「加入這一餐 → 記到午餐」，寧可多按一下，也不要依情況變成不同的流程。
- 純前端、沒有後端。
- 使用者資料不送第三方。**例外（2026-11-18 決定）**：AI 辨識由使用者自己在設定開啟、用自己的 Gemini API Key，預設關閉；條碼查詢只送出條碼號碼。兩者都要在畫面上和 `privacy.html` 說明。
- 既有資料不能壞：只加欄位，不改名、不刪。

## 已決定的事（2026-11-18）
- **API Key 只存本機**（`meta`），不進同步檔、不進備份檔；每台裝置、每個人各自設定。要有測試確認匯出檔裡沒有 Key。
- **AI 分兩處**：
  - 主程式內（設定開啟，預設關閉）：(A) 拍餐點／一句話拆成品項放進購物車、(B) 拍包裝營養標示。附大字教學頁：到 Google AI Studio 按「Get API key」建立、貼回 App；說明免費、不用綁卡、免費方案資料可能被 Google 用來改進模型、Key 只存在這台手機；進階可限制 Key 只能用在 `https://ericckfeng.github.io/*`。
  - **另一個獨立小工具**：(C) 拍書頁表格批次建檔，匯出食物 JSON，主程式用「匯入自訂食物庫」讀入。兩者靠食物 JSON 格式交接，**不共用 localStorage**（同網域技術上可以，但寫壞會弄壞 `diet_tracker_v2`）。
  - 書本營養表有著作權：可個人匯入或由營養師分享 JSON 檔，不放進公開的內建資料庫；內建資料只用 TFDA 等開放授權來源。
- **小芽當寵物貓**：名字仍叫「小芽」，造型改成小貓。依狀態換表情／動作（喝水達標、蛋白質達標、睡飽、睡太少打瞌睡、聚餐後吃飽圓滾滾），點牠會有反應；提醒一天有上限、語氣不責備；可自訂語錄；累計減重里程碑（例如 -1kg ＝ 少背 2 瓶大寶特瓶）。不另外新增角色。
- **熱量銀行要做**，設定裡開關，預設關閉。

## 建議順序

### 0. 同步相容性（必須最先、單獨發佈）
- 問題：`mergeData()` 只回傳固定幾組資料，舊版 App 同步時會把不認得的**最上層資料**（例如自訂食物庫、套餐）丟掉再上傳，造成雲端和其他裝置的資料消失。
- 做法：讓 `mergeData` 保留未知的最上層資料（陣列以 `id`＋`updatedAt`＋tombstone 合併，物件以修改時間比較），補單元測試和新版備份檔樣本，更新 `DATA_FORMAT.md` 的規則 5。
- 這版發佈後，**等使用者裝置都更新**，才發佈會寫入新最上層資料的功能。
- 進度（2026-11-18）：程式與測試完成（App v9）。`sw.js` 對自己的檔案都會先向伺服器確認最新版，所以裝置只要連網開過一次 App 就會是 v9；會出問題的只有「發佈前就開著、一直沒重新載入的舊分頁」。發佈後約等一週，再發佈第 1 段的寫入功能。
- 另外注意：舊版存「每日目標」會重建整個 `targets` 物件，新欄位會被洗掉。新欄位設計成「沒有＝手動／已鎖定」就安全。

### 0.5 新裝置的歡迎畫面（v10，2026-11-19）
- 新裝置打開是全空白，使用者不知道可以登入 Google 取回資料。不強制登入（LINE 內建瀏覽器無法登入 Google、有人不用雲端、離線也要能用）。
- 只在「這台裝置沒有資料、也沒連結雲端」時出現三個大按鈕：以前用過要取回資料（登入 Google）／我有備份檔／第一次使用直接開始。選過就不再出現（`meta.welcomed`，只存本機）。
- LINE 等內建瀏覽器：說明改用 Safari／Chrome 開啟，不跳去 Google。
- 從空白裝置第一次連結成功時，提示「已取回 N 天的記錄」並回到記錄頁。

- 各餐別旁「複製昨日同餐」。
- 資料：新增 `combos`（要同步、要 tombstone、要 `updatedAt`），`mergeData` 要補測試。
- 進度（2026-11-19，v12）：「和昨天一樣」完成：首頁「吃了什麼」下方，這天還沒記、前一天有記的餐別各一個大按鈕（記一樣的，不含照片，可復原）。套餐（`combos`）等 11/26 之後。

  - 生熟重換算係數只在食物有定義時才出現切換；優先直接收錄熟食品項（白飯、雞胸肉（熟））。
- 內建 TFDA「食品營養成分資料庫」整理成精簡 JSON（離線可用、加進 `sw.js` 的 `CORE`；注意檔案大小與授權標示）。數值一律取自資料庫，不自己估。
- 進度（2026-11-19）：轉換程式 `scripts/build_foods.py` 完成，`tfda_foods.json` 已產生（2025-UPDATE1，2,213 筆，437 KB；kcal 用「修正熱量」；只收營養標示上有的項目：熱量、蛋白質、脂肪、碳水、糖、鈉）。App 還沒讀它。
- 欄位決定（2026-11-19）：食物資料只放**營養標示上看得到的數字**，不加膽固醇、鉀等標示上沒有的欄位。原因：自訂食物多半照包裝標示輸入，資料庫欄位比標示多，就會有很多記錄算不進去，合計不完整，反而沒有意義。

  - v23：體組成（InBody、健身房或家用八極體脂機）：(1) 同一天有體重＋體脂率 → 去脂體重 → Katch-McArdle 基礎代謝（370 + 21.6 × 去脂體重），試算頁基礎代謝三選一：體脂機顯示的／用體脂率算的／公式；熱量銀行的底線也用它。(2) 骨骼肌欄位 `smm`：最近兩次比較（間隔 120 天內，最近一次在 14 天內才提醒），減重時骨骼肌少 0.5 kg 以上，小芽／小提醒、報告本週重點、週報都會說；體重下降、肌肉增加會歡呼。(3) 目標體脂率 → 目標體重（去脂體重 ÷ (1 − 目標體脂率)），附國健署參考（男 25%、女 30%）。v24：內臟脂肪等級、相位角、細胞外水分比加成記錄欄位（只記錄、報告列給營養師看）。v25：加內臟脂肪面積（較早的 InBody 機型給面積不給等級，也沒有相位角）。v26：四肢骨骼肌指數 SMI：記四肢肌肉量合計 `asm`（可輸入手腳四個數字自動加總），SMI 用身高計算；偏低（AWGS 2019 BIA：男 < 7.0、女 < 5.7）時，試算頁選減重會提醒、報告本週重點會列出。

### 4. 進階功能（設定開啟，預設關閉）
- 進度（2026-11-19，v22）：熱量銀行完成（`js/bank.js`）。開關在「每日目標」（`targets.bank`，會同步，預設關閉）。補充的規則：一週是週一～週日；這週今天以前沒記錄的日子當作吃了基準量；今天的建議只看今天以前的日子（今天吃東西不會讓目標跳動）；少吃存下來的每天最多加回 300 kcal；營養師的基準低於 1200 時以基準為底線。首頁「今日吃了」的目標、營養素目標用調整後的數字；右上「目標」、趨勢、報告、小芽仍用每日基準。
- **熱量銀行**：週預算＝每日基準 × 7，首頁顯示進度；超標或少吃的差額平均攤到本週剩下的天數。安全底線：今日建議不低於 BMR 或 1,200 kcal，下修時蛋白質不減，只扣碳水和油脂。
- 進度（2026-11-19，v27）：AI 辨識 (A)(B) 完成（`js/ai.js`）。**改用 `generateContent` 端點與 `gemini-flash-latest` 別名**（備用 `gemini-3.5-flash-lite`）：`gemini-2.5-flash` 2026-12-01 起會被轉走；新的 interactions API 要求的 `Api-Revision` 標頭會被瀏覽器 CORS 擋掉（實測 preflight 403），網頁不能用。(A) 首頁「AI 幫我認」：拍照或說一句（語音輸入 zh-TW）→ 品項清單勾選 → 放進查食物的購物車（同一套「加入這一餐 → 記到午餐」），可改克數，照片存在第一樣。(B)「自己輸入」頁拍營養標示 → 填名稱、每份熱量、三大營養素；「存入個人食物庫」等 11/26 之後的 `customFoods`。尚未用真的 Key 實測（測試都用假的 API 回應）。

## 目前不做
