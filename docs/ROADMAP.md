# 改進構想（ROADMAP）

討論用的清單，不是承諾。做之前先跟使用者確認範圍；動到資料格式要先讀 `DATA_FORMAT.md` 的相容性規則。

## 原則（所有構想都要符合）
- 長輩好用：大字、大按鈕、一頁只做一件事，不把功能塞回首頁。
  - （2026-11-19 使用者改變決定）原本「常吃清單按一下就記」的流程**不保留**，第 1 步改成「我的食物」，記法統一成「選食物 → 克數（預填平常的份量）→ 加入這一餐 → 記到午餐」。
- **同一件事只有一種操作方式**（2026-11-19 決定）：例如記一樣和記多樣都是「加入這一餐 → 記到午餐」，寧可多按一下，也不要依情況變成不同的流程。
- 純前端、沒有後端。
- 使用者資料不送第三方。**例外（2026-11-18 決定）**：AI 辨識由使用者自己在設定開啟、用自己的 Gemini API Key，預設關閉；條碼查詢只送出條碼號碼。兩者都要在畫面上和 `privacy.html` 說明。
- 既有資料不能壞：只加欄位，不改名、不刪。

## 已決定的事
- **API Key 只存本機**（`meta.ai`），不進同步檔、不進備份檔；每台裝置、每個人各自設定。有 e2e 測試確認匯出檔裡沒有 Key。
- **AI 分兩處**：
  - 主程式內（設定開啟，預設關閉）：(A) 拍餐點／一句話拆成品項放進購物車、(B) 拍包裝營養標示。（v27 已完成）
  - **另一個獨立小工具**：(C) 拍書頁表格批次建檔，匯出食物 JSON，主程式用「匯入食物」讀入。兩者靠食物 JSON 格式交接，**不共用 localStorage**（同網域技術上可以，但寫壞會弄壞 `diet_tracker_v2`）。
  - 書本營養表有著作權：可個人匯入或由營養師分享 JSON 檔，不放進公開的內建資料庫；內建資料只用 TFDA 等開放授權來源。
  - 模型：用 `generateContent` 端點＋`gemini-flash-latest` 別名（見下方 v27 紀錄）。
- **「常吃的」拿掉，全部重來**（2026-11-19 使用者決定）：第 1 步上線時，「常吃的」清單（`quickItems`）和預設的外食快選（f1～f17）都不再出現，由「我的食物」（`customFoods`）取代，**不把舊清單轉過去**，使用者自己重新建立。**已經記進每天的記錄一律保留**，少了營養素的就照舊，不補、不改。
  - `quickItems` 欄位不刪（相容性規則：只增不刪；舊版 App 同步、舊備份檔匯入都還會用到），只是新版不再顯示、不再新增。
- **不會建檔也能記**（2026-11-19 確認）：「✋ 估份量」（營養師教的手掌法則）、「📷 拍照記」（先拍、標「暫估待修」，留給營養師算）、「✏️ 自己輸入」三種記法**保留不動**。「我的食物」是給想精準記的人，不會建檔的人不用碰。
- **機構資料庫**（2026-11-19 使用者決定，**先給自己和營養師用**）：衛福部以外的權威資料（例如三總、糖尿病衛教學會的食物份量表）**各自一個資料庫，不併進 TFDA**。
  - 原因：(1) 這些多半有著作權，不能內建在公開的 App，只能每個人自己匯入或由營養師分享檔案；要內建給所有人，得先取得各機構授權。(2) 同一樣食物各機構的數字常不同（取樣、份量定義不同），分開才知道是用哪一套算的，也不該平均。
  - 來源資訊（機構、表名、版本／年份、出處）**寫在檔案內容裡**；檔名也加註來源方便人看（例如 `食物資料_三總外食_2024.json`），但檔名傳 LINE、存雲端常被改，App 讀的是內容。
  - 查食物：打關鍵字跨所有資料庫搜尋，每筆標來源；上方一排按鈕可以只查某一個資料庫（衛福部／我的食物／三總…）。
  - 記錄：每筆存來源名稱（快照，資料庫刪掉也還在），首頁記錄和營養師報告多一小行「資料來源：三總外食表 2024」。
  - 有些表是「以份計」（例如「一碗牛肉麵＝主食 4 份、蛋白質 2 份、油脂 3 份」，沒有克數）：食物格式要支援每份的營養素與六大類份數，選到時問「吃了幾份」而不是幾克。
- **加「膳食纖維」欄位**（2026-11-19 使用者決定）：原本「只放營養標示上看得到的數字」的例外。三總圖鑑每樣都有、對血糖和排便有用。維生素等其他營養素仍不加。
  - 和原本的顧慮一樣，很多記錄不會有纖維，所以合計時要註明「有填纖維的 N 筆」，不要讓人誤以為是全部。
  - 第 1 步的食物格式、第 4 步的 CSV 範本都加這一欄；`tfda_foods.json` 當初拿掉了纖維（commit f2f103e），做第 1 步時一起加回來（`build_foods.py` 加欄位、跑差異確認）。
- **書上的資料只取數字、轉成自己的格式**（2026-11-19 使用者決定）：不存書上的照片、不照抄排版；營養數字本身是事實。文字敘述（例如營養師小叮嚀）不逐字照抄，改成自己的話寫進備註。整本系統性整理仍照「先給自己和營養師用」，不內建給所有使用者（書的版權頁有「版權所有 翻印必究」）。
- **用標準 CSV 匯出、也能匯入**（2026-11-19 使用者決定，**只用 CSV，不做 .xlsx**）：我的食物、機構資料庫都能匯出成 CSV 給營養師或其他人（Excel 直接開）；營養師也可以照同一個範本在 Excel 建表、存成 CSV 傳回來匯入。格式見第 4 步。
- **小芽當寵物貓**：名字仍叫「小芽」，造型改成小貓。依狀態換表情／動作（喝水達標、蛋白質達標、睡飽、睡太少打瞌睡、聚餐後吃飽圓滾滾），點牠會有反應；提醒一天有上限、語氣不責備；可自訂語錄；累計減重里程碑（例如 -1kg ＝ 少背 2 瓶大寶特瓶）。不另外新增角色。

同一種檔案格式用在三件事：分享我的食物、機構資料庫、第 6 步 AI 建檔小工具的產出。**要先定下來**。
- 檔案格式（JSON）：`{ app: 'diet-tracker-foods', version: 1, exportedAt, pack: { id, name, org, title, edition, url, note }, foods: [...] }`
  - `pack`：來源資訊（例如 `{ id: 'tsgh-eatout-2024', name: '三總外食表 2024', org: '三軍總醫院', edition: '2024' }`）；分享我的食物時沒有 `pack`。
  - `foods` 和 `customFoods` 同形狀（`per100g` 或 `perServing`）。
- 機構資料庫存在最上層清單 `foodPacks: [{ id, name, org, edition, url, note, foods: [...], updatedAt }]`：整包加入、整包更新、整包刪除，會同步到自己的其他裝置。不放進公開的 App 程式碼。
- 匯入：選檔 → 顯示「三總外食表 2024，共 312 筆」→ 新的資料庫直接加入；同 `id` 的資料庫問「換成新版／保留舊版」。我的食物則可選「只新增不重複」或「同名的更新數值」。
- 匯出：我的食物（可依分類勾選）或整個機構資料庫 → JSON（給 App 用，完整）或 CSV（給人看、給營養師）。
- **CSV 範本（標準格式）**：
  - 依 RFC 4180：逗號分隔、換行 CRLF、含逗號／引號／換行的欄位加雙引號（引號寫兩次）；UTF-8 加 BOM（Excel 開中文不會亂碼）。沿用 App 現有的 `csvCell`／`toCSV`。
  - **第一列是欄位名稱，之後一列一樣食物，不加任何說明列、空白列、合併儲存格**。
  - 欄位（固定順序、中文名稱）：名稱、別名（多個用「、」分隔）、分類、計量方式（`每100g` 或 `每份`）、每份克數、份量說明、熱量(kcal)、蛋白質(g)、脂肪(g)、碳水(g)、糖(g)、鈉(mg)、膳食纖維(g)、全穀雜糧(份)、豆魚蛋肉(份)、蔬菜(份)、水果(份)、乳品(份)、油脂與堅果種子(份)、條碼、備註、資料來源、版本、出處。
  - 計量方式 `每份`：營養素和份數**照書上一整份的數字填**（不要自己換算）；有填「每份克數」→ App 換算成每 100 g，選到時預填這個克數（以克計）；沒填 → 以份計，選到時問幾份。
  - 備註：食材組成、營養師小叮嚀等，用自己的話簡短寫（例如「約等於 9 分滿的飯」），選到這樣食物時顯示。
  - 匯入時自動對照常見的舊名稱：醣類→碳水、主食類→全穀雜糧、肉類／魚肉豆蛋類→豆魚蛋肉、油脂類→油脂與堅果種子、蔬菜類→蔬菜、奶類→乳品；對不上的再讓使用者對照。
  - 來源資訊（資料來源、版本、出處）**每一列都帶**：標準 CSV 沒有放檔案說明的地方；每列都有，排序、篩選、複製部分列到別的表也不會掉。匯入時取第一列的來源當資料庫名稱，若各列不同就問使用者。
  - 數字只寫數字，不加單位（單位在欄位名稱裡）；**空白＝不知道**，不是 0。
  - 匯入：欄位名稱對不上時（例如營養師自己的表），匯入前讓使用者對照每一欄；列出會新增幾筆、有問題的列（例如熱量不是數字）。也接受沒有 BOM、Big5 存的檔案（偵測編碼）。
  - 安全：匯出時，文字欄位開頭是 `=`、`+`、`-`、`@` 的加一個 `'`，避免 Excel 當成公式執行（CSV 注入）；匯入時把這個 `'` 拿掉。
- 記錄的來源註記：飲食記錄新增選填欄位 `src`（資料庫 id）和 `srcName`（名稱快照）；首頁記錄、營養師報告、CSV 都顯示。
- 寫進 `DATA_FORMAT.md`，附 JSON 與 CSV 範本樣本檔、測試（含「資料庫刪掉後，記錄上的來源名稱還在」）。
