# 改進構想（ROADMAP）

討論用的清單，不是承諾。做之前先跟使用者確認範圍；動到資料格式要先讀 `DATA_FORMAT.md` 的相容性規則。

## 原則（所有構想都要符合）
- 長輩好用：大字、大按鈕、一頁只做一件事，不把功能塞回首頁。
  - （2026-11-19 使用者改變決定）原本「常吃清單按一下就記」的流程**不保留**，第 1 步改成「我的食物」，記法統一成「選食物 → 克數（預填平常的份量）→ 加入這一餐 → 記到午餐」。
- **同一件事只有一種操作方式**（2026-11-19 決定）：例如記一樣和記多樣都是「加入這一餐 → 記到午餐」，寧可多按一下，也不要依情況變成不同的流程。
- 純前端、沒有後端。
- 使用者資料不送第三方。**例外（2026-11-18 決定）**：AI 辨識由使用者自己在設定開啟、用自己的 Gemini API Key，預設關閉；條碼查詢只送出條碼號碼。兩者都要在畫面上和 `privacy.html` 說明。
- 既有資料不能壞：只加欄位，不改名、不刪。

## 已決定的事
- **API Key 只存本機**（`meta.ai`），不進同步檔、不進備份檔；每台裝置、每個人各自設定。有 e2e 測試確認匯出檔裡沒有 Key。
- **AI 分兩處**：
  - 主程式內（設定開啟，預設關閉）：(A) 拍餐點／一句話拆成品項放進購物車、(B) 拍包裝營養標示。（v27 已完成）
  - **另一個獨立小工具**：(C) 拍書頁表格批次建檔，匯出食物 JSON，主程式用「匯入食物」讀入。兩者靠食物 JSON 格式交接，**不共用 localStorage**（同網域技術上可以，但寫壞會弄壞 `diet_tracker_v2`）。
  - 書本營養表有著作權：可個人匯入或由營養師分享 JSON 檔，不放進公開的內建資料庫；內建資料只用 TFDA 等開放授權來源。
  - 模型：用 `generateContent` 端點＋`gemini-flash-latest` 別名（見下方 v27 紀錄）。
- **「常吃的」拿掉，全部重來**（2026-11-19 使用者決定）：第 1 步上線時，「常吃的」清單（`quickItems`）和預設的外食快選（f1～f17）都不再出現，由「我的食物」（`customFoods`）取代，**不把舊清單轉過去**，使用者自己重新建立。**已經記進每天的記錄一律保留**，少了營養素的就照舊，不補、不改。
  - `quickItems` 欄位不刪（相容性規則：只增不刪；舊版 App 同步、舊備份檔匯入都還會用到），只是新版不再顯示、不再新增。
- **小芽當寵物貓**：名字仍叫「小芽」，造型改成小貓。依狀態換表情／動作（喝水達標、蛋白質達標、睡飽、睡太少打瞌睡、聚餐後吃飽圓滾滾），點牠會有反應；提醒一天有上限、語氣不責備；可自訂語錄；累計減重里程碑（例如 -1kg ＝ 少背 2 瓶大寶特瓶）。不另外新增角色。

## 現在：等使用者
- **AI 辨識用真的 Key 實測**（v27 的測試都是假的 API 回應）：設定 → 拍一餐 → 用說的 → 拍營養標示，各試一次；有錯誤就截圖。實測沒問題，再做下面第 2 步。

## 11/26 之後（依序做，每一步單獨發佈）

**為什麼要等 11/26**：v9（11/18）以前的 App 同步時會把看不懂的「最上層資料」丟掉再上傳，會讓雲端和其他裝置上的套餐、自訂食物消失。v9 起會原樣保留。等一週讓所有裝置都更新到 v9 以上。

**排序原則**：先做「別的功能都要用到」的基礎（個人食物庫），再做用到它的功能；小的、風險低的先做；獨立程式（AI 建檔小工具）最後。

### 第 0 步：發佈前確認（11/26 當天）
- 請使用者把**每一台用過 App 的手機、電腦**（包括家人的）都連網打開一次 App，確認首頁有「🔍 查食物・秤克數」按鈕（有就代表至少是 v11，v9 以上就安全；App 本身沒有顯示版本號）。只要有一台還沒有這個按鈕，就先不要發佈第 1 步。
- 第 1 步是第一個寫入最上層新資料的版本：**只放個人食物庫**，不和其他功能一起發佈，出問題時容易找原因、容易退回。

### 第 1 步：「我的食物」`customFoods` 取代「常吃的」（基礎，其他都要用到）
- 已決定：「常吃的」拿掉，全部重來（見上方「已決定的事」）。這一步同時做「新增我的食物」和「拿掉常吃的」，一起發佈，中間不能有「兩邊都沒有」的空窗。
- 要一起改的地方：
  - 首頁「⭐ 常吃的」→「⭐ 我的食物」：列出我的食物（最常記的排前面）→ 點一下進克數頁，**預填這樣食物平常的份量**（`serving.g`）→ 加入這一餐 → 記到午餐。常吃的東西還是三下就記好。
  - 下方分頁「快選」（外食快選清單、新增快選視窗、恢復預設快選）→「我的食物」管理頁。
  - 「自己輸入」頁的「加到『常吃的』清單」→「也存到我的食物」（要填每份幾克；不知道就不能存，只記這一次）。
  - 桌面捷徑 `?go=quick` 和 manifest 的「常吃的」→ 改指向我的食物。
  - 小芽、首頁空白時的提示文字裡的「常吃的」。
  - 「熱量資料來源」說明裡外食快選的部分（估份量的代換表說明保留）。
  - 測試：拿掉常吃清單的 e2e，舊版備份檔（含 `quickItems`）仍要能匯入，匯入後資料還在、只是不顯示。
- 資料：最上層清單 `customFoods: [{ id: 'cf_xxxx', name, aliases[], category, per100g: { kcal, p, c, f, sugar, na }, serving: { g, label }, exPer100g, barcode, source, updatedAt }]`
  - 以 `id`＋`updatedAt` 合併，刪除用 `tomb['customFoods:<id>']`（`js/sync.js` 的 `mergeExtra` 已支援，不用改合併規則）。
  - 欄位和 `tfda_foods.json` 一樣，`foods.js` 的克數換算、六大類（`exPer100g` 已支援）、搜尋都能直接用。
  - 只放營養標示上看得到的數字（和 TFDA 資料的決定一樣）。
- 畫面：
  - 查食物的搜尋結果，「我的食物」排在 TFDA 前面，標一個「我的」。
  - 新增／修改頁（大字，照包裝標示填）：名稱、每份幾克、每份熱量、蛋白質、脂肪、碳水；存的時候換算成每 100 g。
  - 管理清單放在「快選」分頁（和常吃清單同一頁、分開兩區）。
- 測試：`mergeData` 合併／刪除、新版備份檔樣本 `backup-v3-custom-foods.json`、舊版備份檔匯入不受影響、`DATA_FORMAT.md` 版本沿革。

### 第 2 步：AI 營養標示 → 存成我的食物（小）
- 「自己輸入」拍營養標示後，多一個勾選「也存到我的食物」（預設勾），存進 `customFoods`（`source: 'ai-label'`）。
- 標示只有每份、沒有每份幾克時：問使用者「一份大約幾克」，不知道就只記這一次，不存成我的食物。

### 第 3 步：套餐 `combos`
- 購物車多一個「存成套餐」；記的時候「選套餐 → 整組放進購物車 → 可以改克數、拿掉 → 記到午餐」（同一套流程，不另外做一鍵直接記入）。
- 資料：最上層清單 `combos: [{ id, name, items: [{ foodId | customFoodId, snapshot: { name, per100g, exPer100g }, grams, weighed }], updatedAt }]`
  - 每一樣都存一份 `snapshot`：TFDA 刪掉的品項（`removed`）、刪掉的我的食物、AI 估的品項，套餐都還能用。
- 入口：「我的食物」頁最上面「我的套餐」，以及查食物頁。

### 第 4 步：食物匯入／匯出（分享給營養師、家人）
- 匯出：勾選我的食物（可依分類全選）→ 下載食物 JSON 檔。
- 匯入：「只新增不重複」或「同名的更新數值」；匯入前列出會新增幾筆、更新幾筆。
- 檔案格式：`{ app: 'diet-tracker-foods', version: 1, exportedAt, foods: [...] }`，`foods` 和 `customFoods` 同形狀（不含 `updatedAt` 以外的同步欄位）。**這是第 6 步 AI 建檔小工具的交接格式**，要先定下來。
- 寫進 `DATA_FORMAT.md`，附樣本檔與測試。

### 第 5 步：條碼掃描
- `customFoods` 加 `barcode` 欄位（第 1 步就先留好）。
- 掃描：`BarcodeDetector`（Android Chrome 可以；**iPhone 不支援**）→ iPhone 改成手動輸入條碼號碼。
- 查詢順序：我的食物（同條碼）→ Open Food Facts（**只送條碼號碼**）→ 都查不到：引導照包裝輸入營養標示（有開 AI 就提供拍標示）→ 存成我的食物並記下條碼，下次掃就有。
- 台灣商品在 Open Food Facts 資料少，要讓「查不到 → 自己建」的路很順。
- `privacy.html` 加說明（Open Food Facts 只收到條碼號碼）。

### 第 6 步：AI 建檔小工具 (C)（獨立程式，最後做）
- 獨立頁面（例如 `tools/foodbook.html`），拍書頁或營養師給的表格 → AI 整理成多筆食物 → 檢查、修改 → 匯出第 4 步格式的 JSON → 主程式「匯入食物」。
- 不共用主程式的 localStorage；API Key 在小工具裡另外貼（也只存在那台裝置）。
- 書本內容有著作權：只給自己或營養師分享用，不放進公開的內建資料庫。

## 之後（還沒排順序）
- **小芽寵物貓**（上面「已決定的事」）：造型、依狀態換表情、里程碑。
- 連續記錄天數的小成就（`buildMascotMessages` 是純函式，好寫測試）。
- 營養師的細目標：每餐蛋白質幾份等；首頁／小芽提醒還差什麼。
- 蛋白質依去脂體重計算（體脂高的人用總體重會高估），等營養師確認倍數。
- 血壓、血糖記錄：每日欄位，用 `setDayField`；血糖一天可能多次（空腹／餐後），要想資料形狀；趨勢圖和報告加欄位。
- 備份提醒：沒開雲端同步的人，超過 14 天沒匯出就提醒一次。

## 目前不做
- 固定時間推播提醒：需要伺服器。
- 開發者提供 AI 服務或共用 Key：會產生費用，也會讓使用者資料經過開發者。
- iPhone 的桌面捷徑：Apple 不支援 manifest 捷徑；iOS 主畫面 App 和 Safari 的資料是分開的，用 iOS「捷徑」App 開網址會看到空白的 App。

## 已完成紀錄（2026-11-18～19）

做法與當時的決定都留著，之後改相關功能時先看這裡。

- **v9 同步相容性**：`mergeData` 保留看不懂的最上層資料（清單以 `id`＋`updatedAt`＋tombstone 合併，物件以修改時間比較）。舊版存「每日目標」會重建整個 `targets`，所以新欄位都設計成「沒有＝手動／關閉」。
- **v10 新裝置歡迎畫面**：只在「這台沒有資料、也沒連結雲端」時出現：取回資料（登入 Google）／我有備份檔／第一次使用。LINE 等內建瀏覽器說明改用 Safari／Chrome。`meta.welcomed` 只存本機。
- **TFDA 食物資料**：`scripts/build_foods.py` → `tfda_foods.json`（2025-UPDATE1，2,213 筆，kcal 用修正熱量）。只收營養標示上有的項目（熱量、蛋白質、脂肪、碳水、糖、鈉），不加膽固醇、鉀等：自訂食物多半照包裝標示輸入，欄位比標示多會讓合計不完整。`js/foods.js`：克數換算、生熟重（只有生肉 ×0.75、生米→飯 ×2.2）、六大類（依分類＋代換表；混合食物不猜）、搜尋（同義詞、多次取樣合併、早餐時段排序）。
- **v11 查食物・秤克數**：記錄新增 `grams`、`foodId`、`weighed`。
- **v12 購物車＋和昨天一樣**：秤克數頁「加入這一餐」→ 查食物頁列出已選品項與合計 →「記到午餐（N 樣）」；每樣各存一筆，一起記的有 `groupId`；有沒記的就離開會問。首頁「吃了什麼」下方，這天還沒記、前一天有記的餐別各一個「記一樣的」。
- **v13 小數修正**：份數、營養素、克數欄位改成 `step="any"`（之前 0.7 份的記錄連改名都存不了）。
- **v14～15 體重 7 日平均線**：平均＝這天和前 6 天「有量的」體重（`rollingAverage`）；趨勢、營養師報告、LINE 摘要的體重變化都看平均（`weightAvgChange`）；每日總表仍列實際體重。
- **v16～17 跨模組提醒**（`js/insights.js`）：吃多後體重上升是水分、睡不到 6 小時、連兩天沒排便、和試算時體重差 2 公斤、骨骼肌流失／增加。由小芽說；關掉小芽的人改在首頁「今天的小提醒」卡片。
- **v18～19 依體重試算目標**（`js/targets.js`）：使用者決定**不自動更新**：按「依體重試算」→ 看建議 →「用這個當我的目標」才寫入；原本有營養師的目標先確認。Mifflin-St Jeor、活動量三個大按鈕（附每天大約步數）、赤字 -300／-500／維持、蛋白質 1.2／1.6／2.0 g/kg、脂肪 0.8 g/kg、碳水回推（至少 100 g）、熱量底線 max(基礎代謝, 1200)、喝水 35 ml/kg（最多 3000，運動每 30 分 +250）。可用體脂機量的基礎代謝。
- **v20 報告本週重點**（`js/highlights.js`）：最多 5 條，✓ 做得好／！可以討論／• 說明；LINE 摘要開頭也有。
- **v21 小芽週報**：上一個完整的週一～週日；做得好的事最多 3 條＋下週可以試的一件事；首頁卡片週一起出現（`meta.weeklySeen`），報告頁隨時可開。
- **v22 熱量銀行**（`js/bank.js`，`targets.bank`，預設關閉）：週一～週日；這週以前沒記錄的日子當作吃了基準量；今天的建議只看今天以前；少吃的每天最多加回 300；底線 max(基礎代謝, 1200)（營養師基準更低時以基準為底）；蛋白質不減、只調碳水和油脂。只影響首頁「今日吃了」。
- **v23～26 體組成**（InBody、健身房或家用八極體脂機）：同一天體重＋體脂率 → 去脂體重 → Katch-McArdle 基礎代謝；試算頁基礎代謝三選一（體脂機／體脂率／公式）；骨骼肌 `smm` 兩次比較；目標體脂率 → 目標體重；只記錄給營養師看的內臟脂肪等級 `vfl`／面積 `vfa`、相位角 `pa`、細胞外水分比 `ecw`；四肢肌肉量 `asm` → SMI（AWGS 2019：男 < 7.0、女 < 5.7），偏低時試算頁和報告提醒。較早的 InBody 機型給內臟脂肪面積、沒有相位角。
- **v27 AI 辨識 (A)(B)**（`js/ai.js`）：`gemini-2.5-flash` 2026-12-01 起會被轉走，改用 `gemini-flash-latest`（備用 `gemini-3.5-flash-lite`）；新的 interactions API 要求的 `Api-Revision` 標頭會被瀏覽器 CORS 擋掉（實測 preflight 403），所以用 `generateContent`，只帶 `content-type`、`x-goog-api-key`。(A) 首頁「AI 幫我認」：拍照或說一句 → 勾選 → 放進購物車，照片存在第一樣，記錄標 `ai`。(B) 自己輸入頁拍營養標示 → 填名稱、每份熱量、三大營養素。
- **v28 桌面捷徑**：manifest `shortcuts`（常吃的、拍照記、喝水、量體重，Android 長按圖示）；`?go=` 網址參數打開對應頁面後拿掉參數。
